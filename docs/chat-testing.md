# チャット機能（段階1）動作確認手順

対象: ローカル環境 / 2026-08-08 時点

## 前提: なぜ「Googleアカウント2つ」だけでは足りないか

アプリのログインは **Google のみ**。一方クリエイター側の画面を見るには、
そのアカウントが `guides.user_id` に紐付いている必要がある。
Googleログインしただけでは誰もクリエイターにならないので、**紐付けコマンドを1回実行する**。

また、購入者と作成者が同一アカウントだとチャットは成立しない（DB制約で弾く仕様）。
**必ず別々のアカウントを使うこと。**

## 事前準備

```bash
supabase start          # 起動していなければ
pnpm dev                # http://localhost:3000
```

## 手順

### 1. アカウントB（クリエイター役）でログインする

1. シークレットウィンドウで http://localhost:3000/login を開く
2. Googleアカウント **B** でログイン
3. ログインできたらそのままにしておく

### 2. アカウントBをクリエイターに紐付ける

```bash
node scripts/link-creator.mjs                      # 一覧確認
node scripts/link-creator.mjs <アカウントBのメール>   # 一覧の先頭のガイドに紐付け
```

紐付いたクリエイターの**パッケージ名が表示される。そのパッケージを次で買う。**
（どのガイドに付くかは一覧の並び順で決まる。指定したい場合は第2引数に guide_id を渡す）

### 3. アカウントA（購入者役）で購入する

1. 通常ウィンドウで http://localhost:3000 を開き、Googleアカウント **A** でログイン
2. 手順2で表示されたパッケージを開く
3. 「購入してガイドを始める」→ Stripeのテストカードで決済

   | 項目 | 値 |
   |---|---|
   | カード番号 | `4242 4242 4242 4242` |
   | 有効期限 | 未来の日付なら何でも（例 `12/34`） |
   | CVC | 任意の3桁 |

4. 購入完了後、パッケージ詳細の下部に**吹き出しアイコン**が出る

### 4. チャットする

1. アカウントA: 吹き出しアイコン → チャット画面 → メッセージ送信
2. アカウントB（別ウィンドウ）: 左ナビ「メッセージ」→ スレッドを開く
3. **両方の画面を並べて表示し、片方から送信** → もう片方に**リロードなしで**表示されればOK

## チェックすべきポイント

### チャット本体

- [ ] 購入**前**はチャットアイコンが出ない
- [ ] 購入**後**にアイコンが出る
- [ ] 送信したメッセージが右（赤）、相手が左（白）に出る
- [ ] **リロードせずに相手の発言が届く**（Realtime）
- [ ] 一覧に未読件数のバッジが出る／スレッドを開くと消える
- [ ] 一覧に相手の名前・アバター・パッケージ名が出る
- [ ] PCで Enter 送信、Shift+Enter で改行。日本語変換中の Enter で誤送信しない
- [ ] 空欄では送信ボタンが押せない
- [ ] スマホ幅（開発者ツールのデバイスモード）でも崩れない

### 権限まわり（重要）

- [ ] アカウントCを別途Googleログインさせ、`/chat` が**空**であること
- [ ] Cが `/chat/<AとBのスレッドID>` を直接開いて**「チャットが見つかりません」**になること

### 今回の変更で影響を受ける既存機能

チャット以外にも手を入れているので、以下も確認してほしい。

- [ ] **ナビが5項目になった** — ホーム/探索/計画/メッセージ/プロフィール。
      スマホ幅で窮屈でないか（気になれば要相談）
- [ ] **言語切替** — 設定→言語設定で英語・韓国語に切り替え、チャット画面も訳されるか。
      メッセージ本文・パッケージ名は**翻訳されないのが正しい**
- [ ] **ログイン** — 再ログイン時にプロフィールが更新される（`upsert` に変更したため）
- [ ] **購入済み判定** — 同じパッケージを2回買っても購入済みのままか（バグ修正済み）
- [ ] **パッケージ詳細** — ヒーロー画像と本文の重なりが無い／価格「3,000円」が改行しない

## うまくいかない時

| 症状 | 原因と対処 |
|---|---|
| チャットアイコンが出ない | 購入が完了していない。または自分自身が作成者のパッケージ（仕様上出ない） |
| 相手の名前が空欄 | `supabase db reset` でマイグレーションを再適用する |
| リアルタイムで届かない | ブラウザのコンソールでWebSocketエラーを確認。`supabase status` で稼働確認 |
| ログインできない | `.env.local` の Google OAuth 設定と、Supabaseの `site_url` を確認 |

## 後片付け

ローカルのテストデータを消すには `supabase db reset`。
デモ用クリエイター3件（`demo.*@tabito.local`）は seed で再作成される。
**本番には流れない**（`supabase/seed.sql` は `db reset` 専用）。
